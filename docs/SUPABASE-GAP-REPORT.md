# تقرير فجوات تحويل BSCH Clinics إلى Supabase

## الحالة الحالية

هذا التقرير مبني على فحص `app.py` و`db_compat.py` وملفات Android والاختبارات الموجودة في الفرع `feature/supabase-migration-20261018`. المشروع لم يتصل بعد بمشروع Supabase، ولم يتم استخدام `SUPABASE_URL` أو `SUPABASE_ANON_KEY` فعلياً. لذلك لا نعلن أن التطبيق يعمل على Supabase في هذه المرحلة.

النسخة الحالية تعتمد على Flask كطبقة API وصلاحيات وجلسات، وعلى SQLite افتراضياً مع دعم PostgreSQL أولي عبر `DATABASE_URL`. واجهة الويب الحالية يمكن إبقاؤها، لكن نقل قاعدة البيانات وحده لا ينقل المصادقة أو منطق السعة أو التحقق أو سجل التدقيق.

## تصنيف الوظائف

| الوظيفة | الوضع الحالي | المسار الآمن المقترح | الحالة |
|---|---|---|---|
| قراءة العيادات والخدمات وأيام العمل | Flask + SQLite/PostgreSQL | Supabase Postgres مع RLS للقراءة العامة للعيادات النشطة | قابلة للنقل |
| إدارة العيادات والإجازات والسعات | Flask يتحقق من الدور ويكتب SQL | Edge Functions أو RPC موقعة للموظفين، مع RLS | تحتاج منطقاً موثوقاً |
| إنشاء الحجز الخارجي | Flask `make_booking` | RPC/Edge Function بمعاملة وقفل صف العيادة | لا ينقل إلى INSERT مباشر من المتصفح |
| منع تجاوز السعة والتعارض | تحقق Python قبل الإدراج | PostgreSQL transaction + `FOR UPDATE`/قيود + دالة مركزية | يجب أن يكون مركزياً |
| الاستعلام العام عن الحجز | حالياً رقم الهاتف وحده | booking number + opaque public token، أو تحقق ثنائي مضبوط | فجوة أمنية يجب إصلاحها |
| دخول الموظفين | جلسة Flask وحسابات محلية | Supabase Auth + `profiles` مرتبطة بـ `auth.users` وRLS | يحتاج إعادة تصميم |
| صلاحيات founder/booking/doctor/nurse | decorator في Flask | `profiles.role` + RLS وEdge Functions للعمليات الحساسة | قابلة للنقل تدريجياً |
| تأكيد/إلغاء/إعادة جدولة/تحويل | Flask مع Queue وAudit | Edge Functions/RPC معاملاتية | لا تنفذ من الواجهة مباشرة |
| شاشة الدور والنداء | Flask وSQLite | RPC/Edge Functions للانتقالات وسجل الأحداث | تحتاج معاملات |
| التقارير | Flask + SQL + CSV/XLSX/HTML | Postgres views/RPC، ويبقى التصدير في Flask مؤقتاً أو Edge Function | Flask مؤقتاً مناسب |
| قوالب ورسائل Incoming/Outgoing | Flask مع parsing وقنوات خارجية | الجداول في Supabase؛ Edge Functions للمعالجة والقنوات | تحتاج خدمات خارجية |
| AI extraction | Flask/`urllib` أو تكامل خارجي | Edge Function مع secret في بيئة الخادم | لا يضع مفتاحاً في التطبيق |
| المزامنة Offline | API مزامنة موجودة جزئياً | Outbox Android + idempotency في Postgres + Edge Function/REST آمن | تحتاج تنفيذ Native |
| النسخ الاحتياطي/الترحيل | سكربت SQLite إلى PostgreSQL | pg_dump/نسخة Supabase + سكربت ترحيل بدون حذف المصدر | يحتاج تشغيل فعلي |

## الفجوات الحرجة قبل اعتماد Supabase

أهم فجوة أمنية حالية أن مسار `/api/bookings/track` يقبل رقم الهاتف وحده ويعيد حجوزات مرتبطة به. قبل جعل المسار عاماً على Supabase يجب استبداله برمز وصول عشوائي غير قابل للتخمين يصدر مع الحجز، أو بآلية تحقق إضافية مناسبة. لا يجوز السماح للواجهة العامة بقراءة جدول الحجوزات مباشرة.

الحسابات الحالية تتضمن مستخدمين افتراضيين بكلمات مرور ثابتة داخل تهيئة SQLite. هذه الحسابات لا يجوز نقلها إلى بيئة إنتاج أو Supabase Auth كما هي. يجب إنشاء حسابات الموظفين من لوحة Supabase Auth/إجراء إداري آمن، ثم ربطها بجدول `profiles`.

دعم PostgreSQL الحالي في `db_compat.py` هو طبقة توافق، وليس بديلاً عن مراجعة SQL. يلزم اختبار `ON CONFLICT`، أنواع الوقت والتاريخ، تسلسل المعرفات، معاملات القفل، والمفاتيح الخارجية على PostgreSQL فعلياً.

تطبيق Android الحالي WebView ببيانات محلية JavaScript؛ لا يوفر Room أو WorkManager أو Outbox مضمونة. لذلك لا ينبغي اعتباره تطبيقاً مركزياً Offline/Online مكتملًا وفق المتطلبات الجديدة حتى تنفذ طبقة Native أو آلية مكافئة مختبرة.

## ما تم تنفيذه في هذه المرحلة

تم إنشاء فرع مستقل من آخر `origin/main`، وتم الحفاظ على نقطة الرجوع السابقة والنسخة الآمنة. أضيف مخطط SQL أولي في `supabase/migrations/0001_initial_schema.sql`، لكنه لم يُطبّق على أي مشروع Supabase بعد. أضيفت تعليمات التشغيل في `supabase/README.md`.

## ما يلزم من صاحب المشروع

قبل تطبيق migration أو اختبار Auth يلزم توفير مشروع Supabase الذي طلبه الملف، أو تفعيل موصل/وسيلة وصول إليه. المطلوب هو استخدام قيم سرية كمتغيرات بيئة فقط، مثل `SUPABASE_URL` و`SUPABASE_ANON_KEY`، ومفتاح قاعدة البيانات أو `service_role` فقط في بيئة خادم آمنة عند الحاجة. لا ينبغي إرسال هذه القيم في الرسائل أو رفعها إلى GitHub.
